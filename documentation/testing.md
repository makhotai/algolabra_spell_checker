### Optimal string alignment and full Damerau-Levenshtein testing

* inserting/deleting/substituting one character or transposing characters results in distance 1
* OSA algorithm cannot edit substring more than once
* full Damerau-Levenshtein distance algorithm can edit substring more than once
* several edit operations have the expected distance
* completely different words have maximum distance
* edit distance by unrestricted version is always less or equal than by restricted version

For OSA I used Hypothesis to test randomly generated Unicode strings. The first test checks that the distance between a string and itself is always 0 and the second one generates two different strings and verifies that their distance is not 0.
For unrestricted version I also used Hypothesis to test randomly generated Unicode strings. The first test is similar to OSA verion and the second one generates two different strings and verifies that their Damerau-Levenshtein distance is <= than OSA distance.
All 4 tests were run with 500 generated examples each.

### Trie

* inserted words can be found
* words that were not inserted cannot be found
* a prefix of a longer word is not considered as complete word itself
* several words with the same prefix are stored and found correctly
* inserting the same word twice does not increase the vocabulary size
* the vocabulary size is updated correctly
* an empty string cannot be inserted

In addition, I used Hypothesis to generate 1000 random example strings and tested that a string inserted into an empty Trie can always be found.

### Spell checker

For the spell checker, I tested the functionality that combines the Trie and OSA/Damerau-Levenshtein distance:
* added words can be found in the vocabulary
* misspelled words are not considered correct
* an exactly matching word is returned with both distances 0
* a word with one substitution/adjacent transposition/insertion/deletion receives the correct suggestion
* the vocabulary can be loaded from a file
* the words returned by the vocabulary are in alphabetical order
* a new word can be added
* an empty string cannot be added
* the same word cannot be added twice
* suggestions sorting order

I also tested the file functionality with a small test word list to check if vocabulary is loaded correctly and that adding a word does not create duplicates.

## Types of inputs for testing

* small text files containing dictionary words
* random strings generated by Hypothesis
* correctly spelled and intentionally misspelled words that have insertion, deletion, substitution and transposition errors (e.g. apple/appl, table/tavle etc)
* words containing non-ASCII characters (e.g. "kynä", "yö", "ångström")
* empty strings
* words with common prefixes (e.g. car/cat/cart) and completely different strings 

## Test reproduction

### Run unit tests

You can run unit tests by using command `poetry run pytest src` 

or just `pytest src` if poetry virtual environment is already activated

### Code coverage

If you want to check the coverage of code and receive visual report you can run:

`poetry run coverage run --branch -m pytest src; poetry run coverage html`

or `coverage run --branch -m pytest src; coverage html`

## Empirical testing

I tested how often the program suggested the correct spelling for a misspelled word. Unfortunately, I could not find a suitable and sufficiently large dataset in Finnish for this purpose. Therefore I used [this list of commonly misspelled words in English](https://en.wikipedia.org/wiki/Commonly_misspelled_English_words) and [this words.txt](https://github.com/dwyl/english-words/blob/master/words.txt) as the basis for the vocabulary. The first list contains misspelled words and their intended correct spellings.

The results were quite predictable.

The dataset contained 257 misspelled words. In 213 cases (~83%), the intended spelling was suggested in first place.

In 35 cases (~13.6%), the program found the intended word but did not rank it first. For example, for the misspelling 'libary', the intended word 'library' had a distance of 1. However, the suggestions were:
```
  libard (distance: 1)
  library (distance: 1)
```
or for 'collegue' and 'colleague', distance is 1 
```
  college (distance: 1)
  colleague (distance: 1)
```

Words with an edit distance more than 2 were not suggested because the max allowed edit distance was 2, e.g. 'defiantly' and 'definitely', distance is 3. 

Only in 8 cases (~3%) the intended correct spelling was not included in the list of suggestions. Mostly, it was due to limit of the list size (max 5). For example, in case of 'prufe' and 'proof', distance is 2. The suggestions were:
```
  prude (distance: 1)
  prune (distance: 1)
  prudes (distance: 2)
  pruh (distance: 2)
  pruned (distance: 2)
```

The test was run using a copy of my program. I did not include the text files or the Python script used to run the spell checker with these word lists in the project repository. However, I can provide them or add them to a separate directory in the repository later.
